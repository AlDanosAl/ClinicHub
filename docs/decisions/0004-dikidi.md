# ADR-0004. Dikidi — временный источник записей только на чтение, затем отключение

- Статус: **принято** (2026-10-16)

## Контекст
Сейчас Dikidi служит основным журналом записи клиники. Официального публичного API у Dikidi нет: есть только неофициальные обёртки, полученные реверс-инжинирингом и работающие по логину и паролю.

## Решение
- До внедрения МИС допускается адаптер `DikidiAdapter`, **только на чтение**: записи на ближайшие дни нужны для напоминаний. Ошибки адаптера не должны валить хаб. Если он перестал работать, админка показывает тревогу, а напоминания можно ставить вручную.
- Учётку для адаптера заводим отдельную, сотрудника с минимальными правами, а не логин руководителя.
- Записывать в Dikidi через неофициальный API **не будем**.
- После внедрения МИС запись переносится туда, а Dikidi отключается. Оставить его витриной можно только по решению руководителя.
