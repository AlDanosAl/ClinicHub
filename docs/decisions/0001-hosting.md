# ADR-0001. Хостинг: физический сервер в клинике + реле без данных

- Статус: **принято** (2026-10-16)
- Участники: Свят, Claude

## Контекст
- Нагрузка небольшая.
- Есть недоверие к VPS: блокировки РКН, физические риски для ЦОД.
- Свят предлагал на первое время хостить всё на своём ноутбуке.
- Сайт должен быть доступен из интернета.
- SIM-телефоны физически стоят в клинике.
- Хранятся данные о здоровье, то есть спецкатегория ПДн по 152-ФЗ.

## Решение
1. **Боевая система работает на выделенном компьютере в клинике**: мини-ПК или отдельный ПК с ИБП. Там же стоят БД, API, сайт и боты.
2. **Ноутбук разработчика используется только для разработки и с тестовыми данными.** Реальная база пациентов клинику не покидает: ноутбук уезжает домой, теряется и попадает в чужие руки. Для спецкатегории ПДн это прямой риск утечки и штрафов.
3. **Сайт публикуется наружу** одним из двух способов:
   - статический белый IP у провайдера клиники + проброс 443;
   - либо обратный туннель (frp/rathole/WireGuard) до маленького реле в РФ. Реле **ничего не хранит**, только проксирует TLS. Если реле исчезнет, поднимаем новое за час, данные целы.
4. **Админка наружу не публикуется**. Доступ есть из LAN или по VPN.
5. **Боты** используют long polling, белый IP им не нужен.
6. **Бэкапы по схеме 3-2-1**, зашифрованные. Одна копия хранится вне клиники.

## Последствия
- (+) Данные физически под контролем, отключения внешних ЦОД не останавливают внутреннюю работу.
- (+) Локализация ПДн в РФ соблюдена.
- (−) Администрирование ложится на Свята: обновления, бэкапы, железо. Нужен регламент.
- (−) Доступность сайта зависит от интернета и электричества клиники. Для сайта клиники это приемлемо.
- Если внешняя нагрузка вырастет, публичную часть без ПДн (статические страницы) можно вынести на хостинг в РФ, ядро оставить локально.
