# ADR-0002. Мастер-данные: МИС — источник правды о пациентах и записях, ClinicHub — о коммуникациях

- Статус: **принято** (2026-10-16)

## Контекст
Сейчас данные о пациентах лежат в нескольких местах: Google-таблица, Dikidi, бумажные карты, ClinicHub. После внедрения МИС к ним добавится ещё одно. Если писать в каждое место независимо, начнутся расхождения.

## Решение
- **До внедрения МИС** мастером пациентов является ClinicHub. Таблица импортируется в него, Dikidi читается только для записей.
- **После внедрения МИС** мастером пациентов, записей, услуг и расписания становится МИС. ClinicHub хранит копию с `MisPatientId` и регулярно синхронизируется: забирает дельту и принимает вебхуки.
- ClinicHub **всегда** остаётся мастером для согласий, привязок мессенджеров, истории сообщений и контента.
- Новый пациент с сайта или из бота создаётся **в МИС** через адаптер, потом его копия приходит в хаб.

## Последствия
- Адаптер МИС обязателен, поэтому наличие API — жёсткое требование к МИС.
- Перед переключением мастера нужна одна разовая миграция: ClinicHub → МИС.
