# CLAUDE.md — правила проекта для Claude (и для людей)

Над проектом работают двое (Свят и AlDanosAl), каждый в своих сессиях Claude под своим аккаунтом.
Сессии не видят друг друга. **Единственная общая память — этот репозиторий.**

## Роли
- **Свят — руководитель проекта.** Общается с заказчиком (клиникой), ставит задачи, принимает архитектурные решения и утверждает ADR.
- **AlDanosAl — разработчик-исполнитель.** Берёт задачи, назначенные ему в GitHub Issues, реализует, проверяет и предлагает идеи. Архитектуру сам не меняет: если видит, что решение лучше поменять, пишет предложение в Issue или PR и ждёт решения Свята.
- Задачи для AlDanosAl ставятся как **GitHub Issue с назначением на него**. Сессия Claude у AlDanosAl в начале работы смотрит открытые Issues, назначенные на него.
- **Вопросы к клинике** (всё, что нужно выяснить или согласовать с заказчиком) сразу записываем в `docs/CLINIC-QUESTIONS.md`. Свят поднимает их при встрече. Не оставляем такие вопросы только в PR, Issue или чате.

## В начале каждой сессии
1. Прочитай `docs/HANDOFF.md` — что сделано, что в работе, что сломано.
2. Прочитай нужный раздел `docs/ARCHITECTURE.md` и связанные `docs/decisions/*`.
3. Проверь `git log --oneline -20`, открытые PR и открытые Issues (свои задачи), чтобы не делать то, что уже сделано в другой ветке.
4. Если задача противоречит ARCHITECTURE или ADR — **остановись и спроси человека**, не переписывай архитектуру молча. Последнее слово по архитектуре за Святом.

## В конце каждой сессии (обязательно)
Добавь запись **в начало** `docs/HANDOFF.md` по шаблону оттуда:
кто (Свят/AlDanosAl), дата, ветка, что сделано, что не доделано, следующие шаги, известные проблемы, принятые решения.
Если принято архитектурное решение — оформи новый ADR в `docs/decisions/`.

## Код
- .NET 10, C#. Решение: `ClinicHub.slnx`. Комментарии, тексты UI и сообщения коммитов — на русском.
- Модульный монолит: новые фичи кладём в `ClinicHub.Api/Modules/<Модуль>/` (см. ARCHITECTURE §3).
- БД: **сейчас SQL Server, перед продом переходим на PostgreSQL** ([ADR-0009](docs/decisions/0009-sqlserver-for-development.md)). Пишем переносимо: только LINQ без сырого SQL, JSON — в текстовой колонке, явные длины строк.
- Время храним в UTC, показываем в Europe/Moscow. Телефоны храним в E.164 (`+79991234567`).
- Секреты (токены ботов, JWT, пароли БД, ключи API) — **никогда** в git. Используем user-secrets / переменные окружения. В репо лежит только `appsettings.example.json`.
- **Персональные данные пациентов в репозиторий не попадают никогда**: ни дампов, ни выгрузок таблицы, ни скриншотов с реальными ФИО. Для тестов есть генератор фейковых данных.
- Миграции EF: перед созданием миграции проверь, не меняет ли схему другая открытая ветка (см. HANDOFF «В работе»).
- Маркетинговые отправки обязаны проходить через проверку согласий (модуль Consents). Обходить её нельзя даже «для теста» на реальных номерах.

## Git
- Ветки: `feature/<модуль>-<кратко>`, `fix/<кратко>` (латиница). В `master` только через PR.
- PR AlDanosAl принимает Свят. Свои PR Свят может принимать сам, AlDanosAl при этом проверяет их работу по поручению (Issue).
- Коммиты небольшие, сообщение отвечает на вопрос «что и зачем».
- Не делай force-push в чужие ветки.
